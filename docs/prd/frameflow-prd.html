01

Product overview

1.1 The opportunity

India's creator economy runs on short video — Reels and YouTube Shorts — but the content that matters most is long-form: Hindi/Hinglish podcasts, talks, kathas, classes and debates. Turning one 60–120 minute episode into 20–50 shorts is today either manual editing (VN, InShot, CapCut-via-VPN) or Western tools that don't understand Indian speech.

No Hindi
OpusClip, the clipping leader, officially doesn't support Hindi or any Indic language; Android app has no editor (2.8★).
2–5 min
Kalakar, the desi-caption specialist, caps videos at 2–5 minutes and doesn't clip. No iOS app.
₹969+/mo
Captions (Mirage) has Indic clipping on mobile, but it's pricey, slow (up to ~1 hr) and its Android Lite app is 3.5★.

Platforms now give away basic captions and dubbing (Edits, Meta AI dubbing, YouTube Create). Value has moved to three places: picking the right moments for Indian audiences, Indic caption craft, and a fast, cheap, reliable workflow on the phones and networks Indian creators actually use.

1.2 Vision & north star

Turn a Hindi/Hinglish podcast into 20 ready-to-post clips — from a phone, in minutes, for less than a chai a day.
North-star metric: clips exported per week — captures selection quality, editor usability and willingness to pay in one number.

2.2 Design principles

1. Preview never waits for a render

Captions, cuts and reframing are drawn live on-device over the source. Rendering happens once, on export.

2. The video is always visible

Split layout: preview on top, tools below. Sheets never cover more than half the screen (Kalakar's biggest mobile flaw).

3. Hinglish is a first-class language

"Hinglish" is an explicit choice; script (Roman / देवनागरी / both) can be switched anytime without re-processing.

4. Money is never a surprise

Cost is shown before any processing. You pay for clips you export, not minutes you upload.

5. Explain the AI

Every clip shows why it was picked (hook, payoff, topic) — not just a score users don't trust.

6. Built for real phones & networks

Works on 3–4 GB RAM Android, resumable everything, background processing, small app size.

Visual language: dark UI (creator-native, makes video pop), saffron→magenta "flow" gradient for primary actions, green/amber scores, Inter + Noto Sans Devanagari. Thumb-zone primary actions; one primary CTA per screen.

03

Product requirements (PRD)

Scope: FrameFlow v1 (MVP) on Android and iOS, plus the backend that powers it. Priorities: P0 required for MVP · P1 fast-follow (Phase 2) · P2 later.

3.1 Goals & non-goals

Goals (MVP)

  • A creator can go from a YouTube link or upload of a Hindi/Hinglish/English video (up to 3 h) to exported, captioned 9:16 clips entirely on a phone.
  • First reviewable clip in < 5 min for a 60-min source (target).
  • Hinglish captions good enough that most clips need ≤ 2 word fixes.
  • ≥ 50% of generated clips judged "postable as-is or with light edits" by beta users (target).
  • Transparent pay-per-exported-clip pricing in INR with UPI.
  • Profitable unit economics at ≤ ₹3 cost per exported clip (target, Phase 0 to verify).

Non-goals (v1)

  • Generative video, AI avatars, text-to-video.
  • Dubbing / voice cloning (platforms give it away).
  • Deep multi-track NLE editing (VN owns this; we match gestures, not depth).
  • Desktop/web editor (web is used only for marketing & account management at launch).
  • Scheduling and direct API posting to every platform (share-sheet first; scheduling P1).
  • Languages beyond Hindi, Hinglish, English in MVP (regional in Phase 3).

Technical architecture

4.1 System overview

Vendor names in "External services" are candidates. Final choices are logged in §4.11 once measured. The system is designed to be vendor-swappable at each stage via a provider interface.

4.2 The clip pipeline (streaming)

A 60-minute source is split into overlapping audio chunks as soon as bytes arrive. Each chunk is transcribed independently; the highlight stage runs over a sliding window of finished transcript (with context from neighbours), so the first clips appear long before the whole episode is processed.

4.3 Clip Spec — the single source of truth

Every clip is a versioned JSON document. The app renders it live (Skia over the proxy video); the render worker turns the same document into an MP4. Editing, undo/redo, templates, presets and reprompts are all operations on this document.

{
  "id": "clp_7Hk2", "projectId": "prj_42", "version": 14,
  "aspect": "9:16",
  "segments": [ { "src": "src_main", "in": 751.20, "out": 799.48 } ],      // up to 3 stitched ranges
  "cuts": [ { "from": 752.10, "to": 752.62, "reason": "filler" } ],      // word deletions
  "captions": {
    "script": "roman",            // roman | devanagari | bilingual

    "words": [ { "t0": 753.04, "t1": 753.31, "spk": "B",
                 "text": { "roman": "paisa", "devanagari": "पैसा", "en": "money" },
                 "style": { "emphasis": true, "color": "#FFD23F" } } ],
    "lineBreaks": [ 3, 7, 11 ], "overrides": { "line:2": { "templateId": "box-bold" } }
  },
  "layout": { "mode": "auto", "followSpeaker": true,
    "scenes": [ { "t0": 751.2, "t1": 770.0, "type": "split", "crops": ["cropA", "cropB"] } ],

Why a spec, not a timeline file

  • Instant, free edits (no server round-trip to see a change).
  • Preview/export parity: one schema, two renderers, golden-image tests.
  • Render caching by spec hash; re-exports cost nothing.
  • Script switch = change one field; all three layers already stored.

Sync model

  • Local-first: edits applied to a local copy (MMKV/SQLite), queued, synced with optimistic concurrency (version).
  • Server stores full versions for undo history & support.
  • Conflicts (rare, single user) resolved last-writer-wins per field group.

4.8 ML strategy & evaluation

ASR bake-off (Phase 0)

  • Eval set: ~50 h of real Hinglish/Hindi podcasts, talks, katha, news; 2–3 speakers; varied mics and noise. Human-verified transcripts for a 5 h subset.
  • Metrics: WER/CER (Roman & Devanagari), code-switch accuracy, proper-noun accuracy, word-timestamp error (ms), diarization error rate, latency, cost/hour.
  • Candidates: Sarvam, ElevenLabs Scribe, Deepgram, Google Chirp, self-hosted Whisper large-v3 variants / AI4Bharat models.

Clip selection

  • v1: LLM over windowed, diarized transcript with genre prompts; structured output; rules for boundaries (complete thought, no cut punchline, hook in first 3 s).
  • Offline eval: overlap with human-picked clips on the eval set; "postable" rate from blind reviewers.
  • Online: keep rate, export rate, post performance.
  • v2: learned ranker on consented keep/discard + views data → India-tuned virality model (moat).

Transliteration & translation

  • Every word stored in Roman, Devanagari and (line-level) English.
  • Consistent Hinglish spellings via normalisation table + brand vocabulary.

Reframe

  • Face detection + tracking with temporal smoothing; active speaker by lip-motion/audio correlation.
  • Eval: % frames with speaker in safe area; jitter metric; manual review set incl. handheld & gaming footage.

Unit cost model (to be filled by Phase 0)

Cost per exported clip = (ingest + ASR + LLM selection + reframe on candidates) ÷ clips exported per project + render + storage/egress + store fee share. Levers: render only on export, reframe only candidate ranges, cache transcripts (reprompt is LLM-only), proxy streaming instead of originals, retention auto-delete. Target ≤ ₹3 per exported clip so that ₹299 for 100 clips carries healthy gross margin after store fees.

4.10 Security & privacy

  • TLS 1.2+ everywhere; at-rest encryption for DB and storage; secrets in a managed vault; no secrets in the app bundle.
  • Short-lived signed URLs for all media; per-workspace access checks on every object; Postgres row-level security.
  • Data retention: originals and renders auto-deleted after 30 days (configurable); transcripts kept for re-editing until project deletion; account deletion purges within 30 days.
  • User content is not used for model training without explicit opt-in; vendor DPAs reviewed (ASR, LLM).
  • DPDP Act readiness: consent records, purpose limitation, grievance contact; accurate App Store/Play data-safety labels.
  • Abuse & rights: rights confirmation, takedown process, rate limits per account/IP, payment fraud checks.
